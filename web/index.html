    What's actually running here

    The order book you're clicking on is the same C++ code that's in the repo, just compiled to WebAssembly so it runs in your browser. Nothing here is faked: every order, match and cancel goes through order_book.hpp.

    The rest of the engine doesn't fit on a website. On Linux there's a TCP server that takes orders, a matching thread pinned to its own CPU core, lock-free queues between the two, UDP market data, and a journal that can replay a whole session exactly. A host like Vercel can't run long-lived servers or open raw sockets, so that part lives in the GitHub repo, along with its tests and benchmarks.
